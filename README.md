# hhbot — бот для hh.ru

Ищет вакансии, оценивает их под ваш профиль, пишет сопроводительные письма, откликается,
ведёт переписку с работодателем и записывает вас на собеседования в свободные слоты календаря.

Работает **только через официальный API hh.ru** (`https://api.hh.ru`) с вашим OAuth-токеном.
Никакого парсинга страниц, обхода капчи и эмуляции браузера. Тексты пишет Claude (Anthropic API).

---

## Что он делает

| Этап | Что происходит |
|---|---|
| Поиск | Обходит ваши поисковые запросы через `/vacancies`, постранично |
| Отсев | Жёсткие фильтры (стоп-слова, зарплата, опыт, тесты hh, чёрный список компаний) — до обращения к модели |
| Оценка | Claude выставляет `fit_score` 0–100, находит совпадения, пробелы и «зацепки» для письма |
| Письмо | Сопроводительное под конкретную вакансию: только факты из вашего профиля, с автопроверкой длины, плейсхолдеров и запрещённых формулировок |
| Отклик | `POST /negotiations` с резюме и письмом, со случайными паузами и дневными лимитами |
| Переписка | Читает новые сообщения работодателей, определяет намерение (приглашение / вопрос / тестовое / отказ / оффер / спам) |
| Собеседования | Сверяет предложенное время с вашим календарём доступности, подтверждает или предлагает свои слоты, пишет встречу в базу и выгружает `.ics` |

**Решение о времени принимает код, а не модель.** Модель только извлекает варианты времени из
сообщения и формулирует текст; попадает ли слот в ваше окно доступности, свободен ли он и не
нарушает ли зазор между встречами — считает `hhbot/scheduling.py`.

## Человек в контуре (по умолчанию)

Бот задуман так, чтобы не наделать от вашего имени глупостей:

* `dry_run: true` — по умолчанию **ничего не отправляется**, вы видите, что бот сделал бы;
* `chat.autopilot: false` — ответы в чате складываются в черновики, отправляете вы (`hhbot drafts send`);
* `chat.auto_confirm_interviews: false` — даже подходящий слот бот не подтверждает без вашего согласия;
* тема письма из списка «только человек» → эскалация: оффер, зарплата, договоры, документы,
  тестовое задание, отказ, признаки мошенничества;
* стоп-слова (`chat.escalate_keywords`) поднимают флаг независимо от мнения модели;
* дневные лимиты на отклики и ответы, паузы между откликами;
* модель не имеет права выдумывать факты: единственный источник данных о вас — блок `profile`.

Чего бот не делает вообще: не проходит тесты hh.ru (такие вакансии пропускает), не торгуется
о зарплате, не подписывает и не отправляет документы, не сообщает паспортные и платёжные данные.

## Установка

```bash
git clone https://github.com/ilgizxamitov-cry/hh.git
cd hh
python3 -m venv .venv && source .venv/bin/activate
pip install -e .

hhbot init          # создаст config.yaml и .env из шаблонов
```

Требуется Python 3.11+.

### 1. Приложение hh.ru

1. Зайдите на <https://dev.hh.ru/admin> и создайте приложение.
2. Redirect URI укажите ровно тот, что в `.env` — по умолчанию `http://localhost:8765/callback`.
3. Полученные `client_id` и `client_secret` впишите в `.env`.
4. В `HH_USER_AGENT` укажите название приложения и **реальный контактный email** — hh.ru
   отклоняет запросы без осмысленного `HH-User-Agent`.

Для личного использования приложения этого достаточно. Если приложением будут пользоваться другие
люди, hh.ru потребует модерацию — в личном сценарии она не нужна.

```dotenv
HH_CLIENT_ID=...
HH_CLIENT_SECRET=...
HH_REDIRECT_URI=http://localhost:8765/callback
HH_USER_AGENT=hhbot/0.1 (you@example.com)
ANTHROPIC_API_KEY=sk-ant-...
```

### 2. Авторизация

```bash
hhbot auth login     # откроет браузер, поймает redirect и сохранит токен в state/tokens.json
hhbot auth status    # проверка
hhbot resumes        # возьмите отсюда resume_id для config.yaml
```

Как это работает: бот открывает страницу `https://hh.ru/oauth/authorize`, вы подтверждаете доступ,
hh.ru редиректит на ваш `redirect_uri`, локальный сервер ловит `code` и меняет его на токен
(`POST https://api.hh.ru/token`). Токен и `refresh_token` лежат в `state/tokens.json` с правами
`0600` и обновляются автоматически за 5 минут до истечения.

Если браузер открывается на другой машине или `redirect_uri` не на localhost — пройдите вход
вручную и отдайте боту ссылку, на которую вас редиректнуло:

```bash
hhbot auth code "http://localhost:8765/callback?code=ABC123&state=..."
# или просто код:
hhbot auth code ABC123
```

### 3. Проверка подключения

```bash
hhbot doctor
```

Проверяет за один заход: ключи в `.env`, формат `HH-User-Agent`, заполненность профиля и поисковых
запросов, наличие и срок жизни токена, доступность `api.hh.ru`, кто авторизован, список резюме и
корректность `resume_id`. Показывает, что именно сделать по каждому провалу.

### 4. Конфигурация

Заполните `config.yaml` (шаблон с комментариями — `src/hhbot/config.example.yaml`):

* `profile` — **самое важное**. Всё, что модель напишет о вас, берётся отсюда. Чем конкретнее
  достижения (с цифрами), тем меньше воды в письмах.
* `searches` — поисковые запросы; параметры один-в-один как в API hh.ru
  ([справочники](https://api.hh.ru/dictionaries), [регионы](https://api.hh.ru/areas)).
* `filters` — что отсекать без вопросов; `min_fit_score` — порог оценки модели.
* `letter` — язык, объём, тон, обязательные и запрещённые формулировки, образцы вашего стиля.
* `availability` — окна, в которые вам можно назначать собеседования, зазор между встречами,
  минимальный запас по времени, чёрные даты.
* `limits` — дневные лимиты и паузы.

## Использование

```bash
# проверить, что всё подключено
hhbot doctor

# посмотреть, что находит поиск (без модели и без откликов)
hhbot search --limit 20 --show-skipped

# прогон откликов вхолостую: покажет оценки и пример письма
hhbot apply

# то же самое, но по-настоящему
hhbot --live apply --limit 10

# разобрать новые сообщения работодателей → черновики ответов
hhbot chat
hhbot drafts list
hhbot drafts show 3
hhbot drafts edit 3 "Свой текст"
hhbot --live drafts send 3

# собеседования
hhbot interviews list
hhbot interviews slots          # ваши ближайшие свободные слоты
hhbot interviews ics -o interviews.ics

# всё сразу: сначала ответы в чатах, потом новые отклики
hhbot --live run
hhbot --live run --loop         # в цикле, интервал из chat.poll_interval_minutes

hhbot stats
```

Флаг `--live` включает реальную отправку и требует подтверждения (снимается `--yes`).
Без него бот работает в режиме `dry_run` из конфига.

### Регулярный запуск

```cron
# каждые 30 минут: ответы в чатах и новые отклики
*/30 * * * * cd /path/to/hh && .venv/bin/hhbot --live run --yes >> state/hhbot.log 2>&1
```

## Как устроено

```
src/hhbot/
├── cli.py          команды (typer)
├── config.py       схема конфига (pydantic) и загрузка YAML
├── auth.py         OAuth 2.0: вход, хранение и обновление токенов
├── api.py          клиент api.hh.ru: троттлинг ~3 rps, ретраи 429/5xx, разбор ошибок
├── models.py       Vacancy / Negotiation / Message + HTML→текст
├── matching.py     жёсткие фильтры и грубая оценка без модели
├── llm.py          Claude: оценка вакансии, письмо, разбор сообщения, ответ (structured outputs)
├── letters.py      проверки письма и повторная генерация при замечаниях
├── chat.py         переписка: намерение → решение по времени → ответ → черновик/отправка
├── scheduling.py   слоты доступности, проверка предложенного времени, экспорт .ics
├── storage.py      SQLite: вакансии, отклики, сообщения, черновики, встречи, счётчики
├── doctor.py       диагностика подключения (`hhbot doctor`)
├── runner.py       оркестрация циклов
└── prompts/        промпты (правки без изменения кода)
```

Состояние — в `state/hhbot.db`. Повторно на одну вакансию бот не откликнется, одно и то же
сообщение работодателя обработает один раз.

Модель — `claude-opus-5` с адаптивным thinking и структурированным выводом; включён серверный
fallback на случай отказа модели (`server-side-fallback-2026-07-01`). Меняется в `llm:` конфига.

## Ограничения, о которых стоит знать

* **Правила hh.ru.** Массовая автоматизация откликов может конфликтовать с пользовательским
  соглашением hh.ru и правилами использования API. Приложение проходит модерацию, у аккаунта
  есть суточные лимиты откликов, а слишком агрессивный темп ведёт к блокировке. Лимиты в
  `limits:` заданы консервативно — не поднимайте их без нужды.
* **Вакансии с тестом** (`has_test`) пропускаются: тест на hh.ru нужно проходить руками.
* **Качество писем** прямо зависит от подробности `profile`. Пустой профиль → общие фразы.
* **Оффер и деньги** бот не обсуждает — это всегда эскалация вам.
* Первые дни держите `autopilot: false` и читайте черновики: так вы быстро настроите тон и фильтры.

## Разработка

```bash
pip install -e ".[dev]"
pytest -q
```

Тесты (72 шт.) покрывают фильтры, календарь и подбор слотов, клиент API (respx: пагинация,
форма отклика, ретраи, разбор ошибок), проверки письма, сценарии чата (подтверждение слота,
эскалация, dry-run, дедупликация сообщений), цикл откликов (лимиты, ошибки hh.ru) и
диагностику подключения.
Обращений к настоящим hh.ru и Anthropic в тестах нет.
